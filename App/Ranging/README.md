# 基础第（3）问：离线自动测距

2026-10-31 更新：当前正式结果来自 DIRECT，LONG 提供时差支持，FRONT 仅作诊断。
当前实现、验证与实板复测条件见 [DIRECT 验证记录](DIRECT_VALIDATION.md)。下文 LONG 正式发布描述为旧基线。

默认输出精简日志；本文日志校验脚本需要的完整结果字段，应通过 `APP_LOG_VERBOSE=1` 启用。
具体格式和切换方法见 [串口日志说明](../LOGGING.md)。

已支持 A/B 任一板在设置页手动设置环境温度，并由主板协调同步双板声速配置。
默认 20 ℃保持原有换算比例；操作、声速模型和 ±2 mm 温补变化验收步骤见
[温度补偿与双板同步](TEMPERATURE.md)。配置在 RAM 中保存。

已合入 `feature/newRanging` 的双板 PCM 导出，并在同一对片段上运行 LONG/FRONT 对照。
LONG 继续决定正式结果，FRONT 仅作诊断，不能以短窗通过推断两屏应该更新距离。
本轮烧录、串口采集、界面字段及固定700 mm实验步骤以 [PCM 串口诊断](../Diagnostics/README.md) 为准。
算法修改前的快照为 `3363294`。本轮先复测原朝向 B 侧 700 mm 困难条件，以及两板整体旋转 180°的
B 侧 700 mm 条件；每组静音 60 秒与播放 90 秒分开采集。

两板麦克风开孔间距 D；声源在基线延长线上。A 为 UID 较小的 MASTER，B 为 SLAVE。
`dt = tB - tA - bias`，`D = c * abs(dt)`；dt 正为 A 侧，负为 B 侧，不除以 2。

## 实现

- 保留第（1）、（2）问的 PTP、D9/PA15 整秒脉冲、采样与声音事件日志。
- 原门限检测用于粗触发；循环缓存保留 256 个触发前采样，完成 2048 点单通道 PCM 片段。
  片段不连续、时钟发生跳变、同步失锁时作废；检查整个片段的原始 PCM 削顶。
- 保留原最少 96 点确认、双阈值和形态门限。形态够而峰值暂不足 `2 * threshold` 的弱候选可延长到最多 480 点，
  期间保留最早门限交点；连续 48 点低于 `threshold / 2` 则作废，避免拼接独立噪声。
  标称 48 kHz 下确认范围约 2～10 ms；强音仍按原 96 点确认。确认完成时间不代替声音到达时间。
- 音频任务对最近 64 个连续 DMA 边界做整数最小二乘拟合，平滑单次边界的帧内相位/IRQ 计时抖动，
  并估计音频采样周期在 PTP 时间域中的长度。断流或 epoch 改变会重建模型，不跨时钟跳变拟合。
- 事件携带本地序号、启动会话、局部时钟 epoch、PTP 起始/粗到达时间及采样周期。
  两板序号和 epoch 不要求相等。按粗到达时间差不超过 20 ms 配对。
- 只有 SyncTask 读写 ETH。在已有 0x88B5 / 56 字节载荷上增加 RNG3 类型，
  B 的 PCM 按 16 点分块发送，逐块 ACK、12 ms 重传，重复块不重复写入。
  会话校验、1.5 s 事务超时与失锁清理防止跨发声、跨重启的数据混用。
- 静态 RangeDSP 任务低于同步、音频和 GUI 的优先级；本轮处理 -127..127 共 255 个整数候选延迟（旧版为 -96..96 共193个），
  按采样周期比例对 B 插值，计算去均值、归一化互相关，再对相关峰做三点抛物线插值。
  最终时间差 = 两片段 PTP 起始时间差 + 插值延迟；不是只把相关峰索引除以 48000。
  量程端点保留 10 mm 误差余量，190~2010 mm 的估计不被提前截断或钳位；实际验收仍按 200~2000 mm 真值与 ±10 mm 判断。
- 相关系数小于 0.65、搜索峰在边界，或距离主峰超过 12 点仍有距主峰小于 0.02 的竞争峰时拒绝。
  这是保守的通用质量门限；长单音容易存在周期歧义，会被拒绝。尚未实现正式标准音频的专用识别。
- 主板统一计算整数毫米距离和方向，发布结果编号与未来 250 ms 的 PTP 显示时刻；
  结果重发并由从板确认。正常通信下，两屏按同一时间更新同一数值。
  网络分区或所有结果 ACK 都丢失时，不能保证两屏原子提交；重新连接会清除旧结果并恢复。
- 屏幕复用 Designer 中的文本和按钮，主屏显示已生效的温度与声速；设置页编辑草稿、应用并查看同步状态。
  没有改动生成文件或新增 QSPI 素材。保留右下角原 LED 按钮。
  设置页“显示单位”可选米或厘米，点击立即生效并高亮所选按钮，无需点击温度“应用”。
  主屏分别显示 `1.234 M` 或 `123.4 CM`，无有效测量时占位符也跟随单位切换。
  单位为本板显示偏好，切换页面后保留，重新上电默认米；温度草稿和测量数据不随单位切换改变。
  `SOURCE A/B SIDE` 表示声源位于 A/B 一侧。
- 主屏同时显示真实同步、事件和测距诊断快照，保留温度、声速与单位切换。
  诊断页支持 SYNC/AUDIO/RESULTS；FRONT 候选单独标注为诊断，不更新有效结果或计数。
  标定、波形页的业务交互尚未接入。

## 编译和烧录

在工程根目录：

```powershell
cmake --build build/Debug -j 8
```

两块板烧录同一个 `build/Debug/DistributedAcousticRanging.elf`，使用现有 CLion/ST-LINK 配置。
不要使用旧 `build/Release` 文件；启动日志应显示 `AUDIO INIT ... confirm=96..480` 和 `RANGE DSP ... lag=-127:127`。
本次仅修改并编译工程，没有替用户烧录硬件。若外部 Flash 原有图形资源还在，本次没有新增外部资源；
若做过全片/外部 Flash 擦除，仍需按本工程既有方法恢复 ELF 中的 QSPI 图形资源。

## 实板测试

1. 两板分别供电，网线接同一交换机（开发自测可直连）。使用板载麦克风，不接额外模块。
   串口均为 USART1 / ST-LINK VCP，1152000、8N1、无流控。
2. 上电两屏先显示 `WAIT SYNC` 和 `-.--- M`。同步收敛后分别为
   `BOARD A/B  SYNC LOCKED`、`WAIT SOUND`。先安静等待音频完成约 1 s 背景学习。
3. 标记两板 channel 0 对应的有效麦克风声孔；两板使用同一通道，量声孔距离，不能量板边。
   先取 1.000 m，两板声孔尽量共线且不互相遮挡；手机在 A 外侧距 A 约 0.5~1 m，音量适中。
4. 播放一次课程标准音频。通常会短暂经过 `TRANSFER`、`CORRELATING`、`WAIT DISPLAY`，
   然后两屏显示相同距离和 `SOURCE A SIDE`；有效编号 ID 和 OK 各增加 1。
   中间状态可能因很短而看不清。串口出现同一 ID、同一 distance_mm 和 source 的 `RANGE RESULT`。
   正常传输的软件设计预算低于 2 s；实际延迟须在双板上验收。
5. 不移动两板，把手机换到 B 外侧，距 B 约 0.5~1 m。距离应基本不变，方向变为 `SOURCE B SIDE`。
6. 分别以 0.200、0.500、1.000、1.500、2.000 m 测试，每一距离、每一声源方向固定位置播放至少 10 次，
   推荐间隔 2 s。不要在同一统计文件中混用距离、方向、音量或重启后的 ID。
7. 两路串口保存为 A/B 日志后运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/ranging/check_results.ps1 `
  -BoardA build/audio-test/board_a.log -BoardB build/audio-test/board_b.log `
  -TruthMm 1000 -ExpectedSource A -ExpectedCount 10
```

脚本按发声配对编号检查两板结果，计算最大绝对误差、样本标准差、两板最大差值和方向。
Pass 要求最大绝对误差 <=10 mm、标准差 <=2 mm、两板差 <=1 mm，且方向全部正确。
它只评估保存的有效测量；另外人工确认每次发声均在 2 s 内输出，记录漏检/拒绝次数，不能只挑成功结果。

8. 安静 60 s，不应新增 ID/OK。断开网线后显示 WAIT SYNC，距离清为空；重连收敛后，再次发声应恢复。
   播放过响时 AUDIO EVENT 的 clipped=1，或片段内削顶，不能作为精度数据。
   低相关/周期歧义时出现 `RANGE REJECT reason=quality_or_range error=N`；
   缺失另一板事件或传输未完成时出现 `timeout_or_unpaired`。拒绝后自动等待下一次声音，保留上次有效结果。
   质量错误码：1=片段无效，2=能量低，3=相关度低，4=相关峰歧义，5=超出量程。
9. 同时检查 AUDIO STATUS 的 drop/timing/hwerr 不持续增加，PTP 仍稳定。
   示波器两通道接两板 D9/PA15 和参考地，验证原整秒脉冲精度没有被新功能破坏。

当前可访问工程没有课程正式音源。可用以下命令生成手机播放的自测扫频 WAV：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/ranging/make_test_audio.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File validation/ranging/run_tests.ps1
```

拷贝到手机，用手机自身扬声器完整播放，不使用蓝牙、不把单个音符交给播放器循环。
主机测试覆盖分数采样相位、采样率差异、增益/直流差异、正负时差、歧义与削顶拒绝、环形缓存跨界、
畸形报文，以及实际双板状态机的丢包、重复包、事件计数不同、局部 epoch 不同、断链和会话恢复。
主机合成数据和编译通过不能证明实物精度达标。

当前归档的五组主要 PCM（10 月 23 日一组、10 月 25 日四组）可用
`python .\App\Ranging\test_algorithm_replay.py --cc gcc --baseline-ref 3363294` 回放。
回放只对比旧的固定采集片段在各搜索范围/算法下的行为，不能模拟新候选确认策略产生的真实起点和完整采样窗口。
重新对齐时缺失的前缀或后缀必须保留缺失标记，不能补零当真实采样。五组或四组旧数据的回放结果不能代替
原朝向 B70 与旋转 B70 的新实测；目录、条件和采集流程详见 [PCM 串口诊断](../Diagnostics/README.md)。

## 声速、相对延迟和精度边界

`range_config.h` 默认声速 343420 mm/s，对应模型 `c=331.3+0.606*T` 的 20 C。
现场温度不同应修改参数并给两板烧录同一固件；本次未实现第五问的现场温度设置。
`RANGE_RELATIVE_BIAS_NS` 为 B 输入链路相对 A 的固定偏差，默认 0，没有伪造标定值。
如需标定，可在已知固定距离处分别从 A/B 两侧发声，取两组**带符号原始时差均值**的平均作为 b；
已启用补偿时，串口 dt_ns 是补偿后的时差，恢复原始值需加回旧 b。标定后保持 b 不变，验证其他距离。

48 kHz 的采样周期约 20.84 us，2 mm 对应约 5.8 us。互相关插值改善采样点之间的定位，
短窗口拟合减小 DMA/PTP 锚点的随机帧内相位影响，但系统性锚点偏差、SAI FIFO、codec 滤波差异、温度、摆放与反射仍会影响结果。
本代码没有硬件捕获每一个采样边沿，也没有声称仅靠插值已满足 2 mm；须按上述步骤实测误差预算。
