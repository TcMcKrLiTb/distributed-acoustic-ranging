# 左右方向差异：首轮实板采集

本轮目的是区分朝向/遮挡、反射、触发与相关算法问题。先用当前固件取得可对照的原始数据。
每组保持相同的固件参数，并记录实际版本；不把任何一个待验证因素认定为根因。

## 测量定义与当前版本

- 当前源码在 `master`；`feature/newRanging` 的算法提交为 `2bd4e0b`，合并提交为 `2de7cdd`。
  每次测试另记实际 HEAD，两板使用同一份 ELF。
- A/B 以开机角色为准：A 是 MASTER，B 是 SLAVE，不能仅凭左右位置命名。
- 当前固定 `MIC_CHANNEL=0`、`INPUT_VOLUME=86`，48 kHz 标称采样。
  先前增益为 80 的录音属于历史条件，不能与增益 86 的录音混作同一组统计。
- 对照测试将两板设为手动 20 ℃，声速为 343420 mm/s；若使用其他温度或自动温补，
  记录实际温度、声速及配置版本，离线重放使用同一声速配置。
- 声音确认范围为 96～480 点；相关残余搜索范围为 -127～127 点。
- LONG 128:1920 决定正式结果；FRONT 128:384 仅输出对照，不更新正式距离。
- 两板有效麦克风声孔间距记为 D；声源到近端板声孔距离记为 d。分别记录，勿混用。
- 声源在外侧延长线上时，`tB-tA = +D/c`（A 侧）或 `-D/c`（B 侧），当前零偏置。
  显示的距离真值为 D。移动声源改变 d，不应改变 D 的真值。
- 任务书的基础量程 0.20～2.00 m 指 D；正式测试规定 d 为 0.5～1 m。
  首轮可取 d=0.7 m，D 保持你目前复现问题时的实际间距。

上电核对下列日志。没有这些字段时，先记录实际版本，不将不同固件的数据混为同一组：

```text
AUDIO INIT fs=48000 ch=0 gain=86 warmup=1s confirm=96..480
RANGE DSP primary=LONG compare=FRONT long=128:1920 front=128:384 lag=-127:127
```

如需重新构建，使用现有 CLion Debug 配置，输出为 `build/Debug/DistributedAcousticRanging.elf`。
不要仅凭仓库分支判断已烧录固件版本。记录 ELF 的 SHA256：

```powershell
Get-FileHash .\build\Debug\DistributedAcousticRanging.elf -Algorithm SHA256
```

## 摆放与对照组

板卡手册 UM1907 Rev 4 的第 11 页标出板背面的两只麦克风 U20/U21，第 32 页是音频原理图。
先标记当前通道实际使用的声孔。源码 channel 0 是数字通道，不能直接按观察者的左/右猜物理位置。
保持声孔不贴桌、不被支架或线缆盖住。不要为了测试拆卸屏幕或添加外置麦克风。

两板声孔与手机实际发声的扬声器尽量共线、同高。左右移动手机后，让同一只扬声器继续朝向两板，
记录手机朝向；避免一组用扬声器正面、另一组用手机背面或手遮住扬声器。

| 组名 | 两板位置及姿态 | 声源位置 | 目的 |
| --- | --- | --- | --- |
| `01_A_original` | B 左、A 右，保持现在的原朝向 | A 外侧，距 A 声孔 d=0.7 m | 原朝向正常侧 |
| `02_B_original` | 与 01 完全相同 | B 外侧，距 B 声孔 d=0.7 m | 原朝向困难侧 |
| `03_B_rotated` | A/B 的左右位置不变；每块板分别绕竖直方向转 180 度 | 与 02 相同 | 朝向对照 |
| `04_A_rotated` | 与 03 完全相同 | 与 01 相同 | 检查差侧是否随朝向翻转 |

旋转时以有效声孔的位置为基准；转完后重新核准 D、d 和高度。
不要把整个阵列调头后让 A/B 对换位置，那会同时改变角色位置与朝向。
若只能先做三组，先做 01、02、03；补齐 04 后更容易判断方向性。

若结果仍不清楚，再做以下独立组，不与上面四组混在一起：

- 恢复原朝向，仅交换 A/B 两块实物板的左右位置，声源仍在空间左侧外侧 0.7 m；
  记录此时近端角色为 A。这有助于判断问题是否跟随某块实物板/主从角色。
- 在困难条件下改变两板及声源的离桌高度，重新保持共线、同高和原 D/d；记录变化。
  该组用于检查桌面反射及支撑遮挡，不作为与原高度完全等价的重复测量。

旋转改善只能支持“板卡整体朝向或声学路径有关”，不能单独证明是 LCD 屏幕造成。

## 每组如何采集

1. 使用一直在测试的同一段声音、同一播放设备、同一音量。优先使用课程标准音频。
   保留播放文件原件，不在同一次采集中换音频、调音量或移动设备。
2. 使用交换机或当前开发接线，等待两板同步锁定，音频完成背景学习。
   关闭占用这两路串口的 MobaXterm 等软件。串口参数为 1152000、8N1、无流控。
3. 原朝向、旋转朝向分别先保存一次 60 秒无声背景，期间不触摸板卡或播放声音。
4. 每个发声组新开一次 90 秒采集；看到 READY 后开始播放。
   每组至少 10 次、推荐 24 次相同短音，间隔至少 2 秒。记录实际发声次数。
   若现有播放文件是连续的 24 次短音序列，完整播放一次即可。
5. 完整保留失败、额外事件、漏检和无结果的采集。文件不足 24 个时不要补删文件来凑数。

在项目根目录执行。例如先做背景，再做 B 侧困难条件：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\App\Diagnostics\capture_pcm.ps1 -Ports COM3,COM8 -DurationSeconds 60 -OutputDirectory .\build\direction-test\00_quiet_original

powershell -NoProfile -ExecutionPolicy Bypass -File .\App\Diagnostics\capture_pcm.ps1 -Ports COM3,COM8 -DurationSeconds 90 -OutputDirectory .\build\direction-test\02_B_original
```

将 COM3/COM8 替换成实际串口；A/B 对应关系以日志及 JSON 的 `board` 字段核对。
其余组使用相应的新目录名。重复某组时加 `_repeat1` 等后缀，避免覆盖。
如需保存完整启动日志，可先打开采集，再复位两板，等待锁定后播放；这时延长至 120 秒。
这段启动日志里的失锁/学习不能误算为稳定测试阶段的故障。

当前固件 `APP_PCM_DUMP=1`，完成录制后会导出 2048 点原始单通道 PCM，覆盖触发前约 5.3 ms，
总长约 42.7 ms。脚本自动生成 `.pcm`、`.wav`、`.json`，并校验 CRC。
没有触发/没有完成录制时没有对应 PCM，因此两路完整 `.log` 同样必需。
WAV 的 48000 Hz 是标称值，离线复算使用 JSON 的 `period_ps`、`start_ns`，不能只读 WAV。

## 上传内容与后续修改依据

把整个 `build/direction-test` 目录打包上传，包含两路 `.log`、所有 `.pcm/.json/.wav`、每组记录。
另外提供原始播放音频，以及能看清屏幕、麦克风和声源位置的俯视/侧视照片。
日志、波形和测试条件缺一时，无法可靠区分漏检、传输失败和错误相关峰。

数据分析按以下顺序进行：

1. 统计实际发声数、两板事件数、完整片段数、配对数、正式结果数与拒绝原因。
   成功率和有效结果的误差/标准差分别报告，不能只挑成功片段。
2. 检查两板噪声、削顶、触发前沿及粗到达时间；按 PTP 时间和启动会话配对，不能假定序号相等。
3. 对同一对波形重放实际 C 算法，比较 LONG/FRONT 的 `q/q2/gap/lag/dt_ns`、方向及相对 D 的误差。
   FRONT 的通过率只能作为诊断，后续若调整选窗，还需新数据验证并保留误选峰检查。
4. 用四组朝向数据区分方向相关的声学路径与固定硬件/角色因素，再决定调整摆放、触发或相关窗口。

一个已确认的源码配置是：`Drivers/BSP/Components/wm8994/wm8994.c` 的
`INPUT_DEVICE_DIGITAL_MICROPHONE_2` 分支向 `0x0450` 写入 `0x00DB`，使能录音路径 DRC。
其他混合输入分支里的关闭 DRC 设置不用于当前路径。使能不等于已证明发生显著压缩或已定位根因。
WM8994 数据手册 Rev 4.6 第 72～83 页说明 DRC 与控制寄存器：
https://statics.cirrus.com/pubs/proDatasheet/WM8994_Rev4.6.pdf

拿到基线数据后，可在相同摆放下单独对照关闭 DRC 的固件（例如该分支 `0x0450=0x0000`），
保持增益、触发及相关门限不变，分别记录版本并重新检查削顶/漏检。
该试验只排除动态处理影响，不保证解决朝向差异。
长窗受后段反射影响、触发位置偏后等假设也需由 PCM 证明，再各自单独修改。

本轮不建议用降低相关系数门限、取相关绝对值或按左右侧分别拟合距离偏置来掩盖拒绝。
搜索的 ±127 点是两个各自触发片段之间的残余对齐范围，不是两板最大间距；最终时差还包含片段起始 PTP 时间差。

本机已通过串口编码/解码、测距核心方向/偏置与歧义合成检查、测距状态机检查。
原文档提到的历史 PCM 在当前工作区不存在，实测重放已跳过；没有实板运行证据，尚未确认根因。
